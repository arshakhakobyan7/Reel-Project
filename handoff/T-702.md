## What to build
1. `google_api.py` — shared by YouTube now and Classroom (T-704) later:
   - `AccessTokens` protocol: `token() -> str` (a valid access token) and `invalidate() -> None`
     (called after HTTP 401; the next `token()` must refresh). T-701 will implement it.
   - A small JSON + raw-bytes HTTP client over `urllib.request` (base URLs injectable): bearer auth,
     one automatic retry after 401 (invalidate first), `GoogleApiError(message, *, status, reason,
     retryable)`. Retryable: timeouts/connection errors, 5xx, 429, `rateLimitExceeded`,
     `userRateLimitExceeded`, `backendError`, `quotaExceeded`/`uploadLimitExceeded` (say in the
     message that the daily quota is used up). Permanent: other 4xx. Never log or put in errors the
     token, the `Authorization` header or upload session URLs.
2. `youtube.py` — `YoutubePublisher(settings, tokens: AccessTokens | None, *, api_url, upload_url,
   chunk_size=8 MiB (multiple of 256 KiB), sleep, ...)` with
   `publish(upload: YoutubeUpload, previous: dict | None, *, on_state, on_progress=None, check=None)
   -> YoutubeResult`.
   - `YoutubeUpload`: job id, `marker` (given by the caller, e.g. `reel-1a2b3c4d-job-42`), video
     path, `file_sha256`, title, description, optional thumbnail path, playlist id (may be empty),
     group name (title for a created playlist).
   - `previous`: the stored `details` dict of an earlier attempt (or `None`); `on_state(details)` is
     called whenever there is state worth saving (right after a resumable session is created, after
     the upload, after the playlist step), so a crash can resume instead of uploading twice.
   - **Privacy:** a module constant `PRIVACY = "unlisted"` used in every body with `status`
     (videos and created playlists); nothing accepts another value. `selfDeclaredMadeForKids: false`.
   - **Metadata:** title ≤ 100 characters, description ≤ 5000 **bytes** UTF-8 (Armenian is 2 bytes
     per letter), no `<` / `>` (YouTube rejects them — replace them), `categoryId`, `defaultLanguage`
     and `defaultAudioLanguage` from settings, tags `[marker, "reel-file-" + sha256[:16]]`.
   - **Resumable upload:** start a session, send chunks with `Content-Range`, handle `308` +
     `Range`, query the session (`bytes */total`) after an interruption or 5xx and continue from the
     confirmed offset with backoff; a 404/410 session → new session only after the marker check below.
     `check()` between chunks (cancellation), `on_progress(sent, total)`.
   - **Exactly once:** before a new upload (no stored video id, no usable session), look for an
     existing video with this `marker` + file tag among the channel's recent uploads (uploads
     playlist from `channels.list mine=true`, then `videos.list` on those ids; a bounded number of
     pages) and reuse it.
   - **Re-run:** stored video with the same `file_sha256` → no upload; update its snippet
     (`videos.update`, include `categoryId`), thumbnail, playlist. Different `file_sha256` → upload a
     new video, put it in the playlist, remove the old one from the playlist; delete the old video
     only if `delete_replaced_videos`, otherwise keep it and list it in the result.
   - **Thumbnail:** `thumbnails.set`; a 403 (channel not allowed custom thumbnails) is a flag
     `youtube_thumbnail_not_set`, not a failure.
   - **Playlist:** given id → add only if `playlistItems.list(videoId=...)` does not have it. Empty
     id: with `create_missing_playlists` find a playlist titled with the group name, else create it
     (unlisted) and return its id; otherwise flag `youtube_no_playlist`.
   - **R-5 check:** after upload `videos.list part=status`: `uploadStatus` `rejected`/`failed` →
     permanent error with the reason; `privacyStatus` not `unlisted` → flag
     `youtube_not_unlisted` (do not try to change it to public or anything else).
   - `YoutubeResult`: video id, watch URL `https://www.youtube.com/watch?v=<id>`, playlist id,
     `created`/`updated`, replaced video ids, flags, `dry_run`, `details` (what T-706 stores; no
     secrets).
3. **Dry-run:** no HTTP call at all and no token needed; return what would be sent (bodies, file
   size, playlist action) with `dry_run=True`. Live mode with `tokens=None` → clear permanent error.

- a retry after an interrupted upload (connection cut mid-chunk, 5xx, process "crash" resumed from

- dry-run makes no API calls;

  values); Armenian title/description sent as UTF-8 intact and limits respected; tokens and session
  URLs never appear in logs or errors (use `caplog`).
