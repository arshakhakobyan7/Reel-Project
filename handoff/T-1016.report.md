## Routes and public API

| Route | Access and result |
|---|---|
| `GET /profile?done=<value>` | `staff` dependency; own facts and prefilled details, with an optional recognized success message. |
| `POST /profile/details` | Own first name, last name, email and phone; 303 to `/profile?done=details` on success, 422 for invalid fields, 409 for an occupied email. |
| `POST /profile/password` | Current password, new password and confirmation; 303 to `/profile?done=password` on success, 422 for a validation failure, 429 when throttled. |
| Existing `POST /login` | Username or current email; a username match takes priority. |

The registration signature, normalization, validation order and Armenian errors remain

Its normalized username/email query uses one lookup, gives username matches priority,
and preserves dummy-hash verification for missing or invalid identifiers.

## Implementation and security

Details collision checking and writing share one immediate transaction. Another
account's username or email remains reserved even when that account is closed.
Username, role, publishing permission, active state and ownership are never accepted
as editable fields.

Password checks follow the required order: shared login throttle, current-password
verification, matching confirmation, strength, then difference from the current
password. A successful change replaces the hash and current browser's session
fingerprint. Other sessions fail on their next authenticated request.

Both forms use the existing CSRF guard. Form limits are enforced on the server.
A route class scoped to the profile routes handles FastAPI field-validation failures
with a safe HTML error: oversized password input is never included in the default
validation JSON. Only the four details fields can be preserved after an outer field
limit fails. Password inputs are always empty on rendered pages.

New profile log messages contain only the account ID, using the two exact requested
message formats. No password or hash enters the template context. User-provided
details are escaped by the existing template environment. CSP and shared CSS are
unchanged; the new template contains no inline styles or scripts.
