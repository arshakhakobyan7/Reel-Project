## Public API and design

```python
@dataclass(frozen=True)
class Chapter:
    start: float
    title: str

class MetadataTextError(ValueError): ...
class ChapterError(MetadataTextError): ...

@dataclass(frozen=True)
class DescriptionResult:
    text: str
    flags: tuple[str, ...] = ()

def format_timestamp(seconds: float, *, long: bool) -> str: ...
def check_chapters(chapters: Iterable[Chapter], duration: float,
                   settings: MetadataSettings) -> list[Chapter]: ...
def render_title(settings: MetadataSettings, *, group: str,
                 lesson: int | str | None, date: Date | str | None,
                 topic: str = "") -> str: ...
def build_description(*, summary: str, chapters: Iterable[Chapter], duration: float,
                      footer_fields: Mapping[str, Any],
                      settings: MetadataSettings) -> DescriptionResult: ...
```

All public values/functions above are also exported from `reel.metadata`.

- Chapters are checked in input order, never sorted. Invalid counts, nonfinite/negative/outside starts, duplicates, out-of-order starts, empty titles and short intervals raise `ChapterError` with a reason. An initial start in the inclusive range 0..`min_chapter_seconds` moves to zero; other fractional starts are preserved. Every chapter, including the last interval to video end, must meet the minimum both in raw time and after timestamp flooring. A 1 ns tolerance handles raw subtraction roundoff without accepting a too-short published interval.
- Titles collapse whitespace to one line, replace `<`/`>` with parentheses (matching the YouTube publisher), and truncate at whitespace word boundaries with an ellipsis. An overlong single word falls back to a character prefix plus ellipsis. Chapter titles honour the configured maximum; video titles are at most 100 Unicode characters.
- Templates use the approved fields and ordinary format specs, with escaped braces supported. Attribute/index access and nested specs are refused. Missing optional values become empty even with a format spec. As clarified by the user, `topic` is used only through an explicit `{topic}` placeholder; it is not appended automatically. Renderer support is implemented; the schema whitelist change below belongs to Claude.
- Description sections are summary paragraph, complete chapter block and optional rendered footer, separated by blank lines. All chapters in a video use M:SS when duration < 3600 and H:MM:SS when duration >= 3600. Seconds are floored, including exactly 1-hour/59:59.9 boundaries.
- The limit is 5000 UTF-8 bytes, including separators and ellipses. Summary space is reduced first. Chapters are never partially emitted: a block that alone exceeds 5000 bytes is dropped. If the remaining fixed chapter/footer content still overflows after sacrificing summary space, only the footer is shortened. UTF-8 characters are never split.

Description flags:

| Flag | Meaning |
| --- | --- |
| `description_chapters_dropped` | The complete chapter block alone exceeded the byte limit and was omitted. |
| `description_summary_truncated` | The summary was shortened or omitted to fit. |
| `description_footer_truncated` | The footer was shortened or omitted after summary space was exhausted. |

An empty chapter input is allowed by `build_description` for T-501's no-chapters fallback; `check_chapters` itself requires the configured minimum count. A malformed nonempty chapter list is not silently discarded.
