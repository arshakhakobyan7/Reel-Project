```python
class AccessTokens(Protocol):

class GoogleApiError(RuntimeError):
    def __init__(self, message: str, *, status: int | None,
                 reason: str, retryable: bool) -> None: ...

@dataclass(frozen=True)

    status: int
    headers: dict[str, str]  # Lowercase names; excluded from repr.
    data: bytes             # Excluded from repr.
    def json(self) -> dict[str, Any]: ...

class GoogleApiClient:

                 allowed_urls: tuple[str, ...] = (), timeout_seconds: float = 30) -> None: ...

                data: bytes | None = None, headers=None, accepted=(200, 201, 204),
                check: Callable[[], None] | None = None) -> GoogleResponse: ...

class SessionCodec(Protocol):
    def seal(self, url: str) -> str: ...
    def unseal(self, protected: str) -> str: ...

class WindowsSessionCodec:  # Implements SessionCodec using current-user DPAPI.
    def seal(self, url: str) -> str: ...
    def unseal(self, protected: str) -> str: ...

@dataclass(frozen=True)
class YoutubeUpload:
    job_id: int
    marker: str

class YoutubePublisher:
    def __init__(self, settings: YoutubeSettings, tokens: AccessTokens | None = None, *,
                 api_url=API_URL, upload_url=UPLOAD_URL, chunk_size=8 * 1024 * 1024,

                on_state: Callable[[dict[str, Any]], None], on_progress=None,
                check=None) -> YoutubeResult: ...
```

## Behaviour and state contract

- `GoogleApiClient` sends bearer-authenticated JSON or bytes with `urllib.request`. A 401
  invalidates the token, obtains a new token and retries exactly once. Connection failures,
  timeouts, 5xx, 429 and the specified Google transient/quota reasons are retryable. Quota
  errors explicitly say the daily quota is used up. Other 4xx are permanent.
- Error messages use static text and allowlisted reason codes, never Google's untrusted free
  text. Tokens/session URLs are registered for redaction; the client does not log requests,
  headers or response bodies. Redirects and proxies are disabled. Absolute session requests
  must have one of the configured API/upload origins; only HTTPS or literal loopback HTTP is
  accepted. Request/response sizes are bounded where appropriate.
- `PRIVACY = "unlisted"` is the only outgoing privacy setting, including created playlists.
  Video status bodies also include `selfDeclaredMadeForKids: false`. Snippets include category,
  both languages, and both required marker/file tags. Titles are limited to 100 Unicode
  characters; descriptions to 5000 UTF-8 bytes without splitting a character. Angle brackets
  become parentheses. Same-file metadata updates send `part=snippet` and include `categoryId`.
- Upload sessions use `Content-Range` chunks (default 8 MiB; validated multiple of 256 KiB).
  308 `Range` acknowledgements determine the next offset. Connection failures and transient
  upload errors trigger exponential backoff and an empty status-query PUT before more data.
  No progress and invalid ranges fail clearly; retries are bounded. Saved sessions are queried
  before resuming. Both 404 and 410 require a fresh marker lookup before another session.
- Before a new upload, the authenticated channel's uploads playlist is scanned, then
  `videos.list` checks both exact tags. Up to `max_pages` pages of 50 recent uploads are scanned
  (default 500). History/API errors propagate instead of triggering a blind upload. A matching
  existing video is reused and its snippet updated.
- The callback receives independent JSON-compatible snapshots at initial intent, immediately
  after session creation, after acknowledged chunks, immediately after obtaining the video ID,
  after playlist creation/selection, after playlist placement, during replacement cleanup and
  at completion. Callback/check exceptions propagate; they are never treated as network errors.
  `check()` runs between chunks and around requests/checkpoints/backoff. Progress reports
  confirmed bytes and total bytes.
- The state contains `version`, `job_id`, `marker`, `file_sha256`, `file_size`, `group_name`,
  `video_id` when known, `upload_offset`, `playlist_id`, `playlist_done`, `complete`, flags and
  replacement records. It validates job/marker identity and never mutates `previous`.
  A new attempt clears completion markers until its work actually finishes.
- `details["session"]`, while present, is a DPAPI-protected string, not a plaintext upload URL.
  This reconciles crash recovery with secret-free persisted details. It is removed when a
  video ID is obtained. The default codec survives publisher/process restarts under the same
  Windows account; no OAuth tokens enter state. A custom secure `SessionCodec` may be injected.
- A same-file stored video ID avoids upload. A different hash checkpoints the old video as a
  retirement, uploads the new file, adds the new video to the playlist, then removes old
  memberships. Old-video deletion requires both a recorded deletion intent and the current
  `delete_replaced_videos=True`; disabling deletion before cleanup preserves it. Cleanup is
  restartable and ignores already-deleted 404/410 resources.
- `replaced_video_ids` lists replaced IDs; `details["retained_video_ids"]` explicitly lists
  those still kept. Retirement records contain the prior playlist, deletion intent, and
  `removed`/`deleted` checkpoints.
- Playlist membership is checked with `playlistItems.list(videoId=...)` before insertion.
  Empty playlist IDs with creation enabled search by group title, then create an unlisted
  playlist only if absent. Incomplete playlist searches fail instead of creating duplicates.
  Creation/selection is checkpointed before membership insertion.
- Uploaded status `rejected`/`failed` is permanent, with a safe rejection/failure reason.
  Unexpected privacy adds `youtube_not_unlisted`; no status-changing request is attempted.
  Permanent thumbnail 403 adds `youtube_thumbnail_not_set`; quota 403 still propagates as
  retryable. Disabled playlist creation with no destination adds `youtube_no_playlist`.
- Dry-run needs no token and constructs no HTTP client. Its details contain metadata, file and
  thumbnail sizes, the concrete upload/update body and method, playlist action/body and planned
  replacement. It returns no fabricated video ID or watch URL. A later live attempt ignores
  dry-run state and performs normal recovery.

## Open questions and known limits

- No unresolved task questions. Live credential verification remains T-1003; none was attempted.
- Google offers no atomic check-and-upload idempotency key. Recovery covers persisted sessions
  and marker matches in the configured recent-upload window; attempts for one job must be
  serialized by T-706. A lost state outside that bounded window or delayed API visibility can
  exceed that recovery guarantee.
- Default session-state protection uses current-user Windows DPAPI. The worker must restart
  under the same Windows identity. Other platforms need an injected secure `SessionCodec`;
  dry-run and the shared HTTP client are platform independent.
- HTTP requests are synchronous with the configured timeout. `check` is cooperative between
  requests/chunks and around backoff; it does not interrupt a socket operation in progress.
- The caller supplies `file_sha256`; the publisher checks file size/mtime during transfer but
  does not hash a potentially large video a second time.

## Official references read

The implementation follows the documented [YouTube resumable protocol](https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol)
for session initiation, status queries, offsets and chunk sizing.
Video operations were checked against [insert](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert),
[list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list),
[update](https://developers.google.com/youtube/data/reference/rest/v3/videos/update) and
[delete](https://developers.google.com/youtube/data/reference/rest/v3/videos/delete).
Thumbnail and playlist operations follow [thumbnails.set](https://developers.google.com/youtube/data/reference/rest/v3/thumbnails/set),
[playlists.list](https://developers.google.com/youtube/data/reference/rest/v3/playlists/list),
[playlists.insert](https://developers.google.com/youtube/data/reference/rest/v3/playlists/insert),
[playlistItems.list](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/list),
[playlistItems.insert](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/insert),
[playlistItems.delete](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/delete) and
[channels.list](https://developers.google.com/youtube/data/reference/rest/v3/channels/list).
Protected state uses Microsoft's [CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)
and [CryptUnprotectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptunprotectdata) APIs.
