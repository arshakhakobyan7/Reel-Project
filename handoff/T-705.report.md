## Design and public API

The local adapter upserts the existing LibraryEntry table by its unique job_id.
INSERT ... ON CONFLICT DO NOTHING ... RETURNING arbitrates competing creates before
reading an existing row, then the row is updated in the same transaction. Its id and
created_at stay fixed; updated_at advances using reel.db.utcnow, including a one-microsecond
advance if the clock is equal/earlier. JSON columns are replaced rather than mutated.

upsert_library_entry accepts the caller's Session, flushes and returns a result without
committing, rolling back, closing or opening another session. LocalLibraryPublisher is
the separate-transaction convenience and uses Database.transaction(immediate=True).
This separation avoids opening a competing writer transaction inside a stage's own
unit of work. Local results return the actual row id as text and url=None: a working
local dashboard/API URL does not exist yet and is not invented here.

HTTP uses one UTF-8 JSON PUT to /entries/{external_key}. The key is
reel-{database.instance_id normalised as 32 lowercase UUID hex digits}-job-{job_id}.
The factory reads the existing AppMeta instance_id; it never creates a replacement
namespace. Recreating a publisher/retrying a job keeps the same key; separate databases
with the same job id get different keys. A lost response after commit is safe to retry.

Responses are strictly checked for exact keys, requested external_key, opaque string id,
HTTP(S) URL, boolean created matching 201/200, and an item echo equal to the validated
request. Malformed JSON/types, duplicate keys, nonfinite numbers, oversized bodies,
wrong identity/item/content type, control characters in ids and unexpected success
statuses cannot produce success. Upstream bodies/exceptions/tokens are never exposed.
Redirects and environment proxies are disabled. No retries or sleeps occur in the client.

LibraryItem copies chapter dictionaries into immutable Chapter values. It preserves
Armenian, accepts nullable lesson/date and empty chapters, validates finite nonnegative
strictly increasing starts, and emits ISO YYYY-MM-DD dates. group maps to LibraryEntry's
group_name; chapters use the task's start_seconds field.

The factory chooses cfg.settings.library.provider, passes the configured URL/timeout,
and obtains the bearer token via cfg.secrets.get("LIBRARY_API_TOKEN"). Missing/invalid
tokens are permanent errors before any HTTP. HTTP 408/429/5xx, socket/connection failures
and invalid responses are RetryableLibraryError; other HTTP errors (including auth
401/403 and redirects) are PermanentLibraryError. Valid Retry-After seconds are exposed
on the exception for the future stage to schedule.

D-016: dry_run=True previews either adapter with its payload, no entry id/URL, neither
created nor updated, and no DB writes or HTTP. HTTP also returns the stable external key.
LibrarySettings has no mode field, so the flag is explicit; no shared setting was added.

The proposed REST contract documents the endpoint, JSON examples, status/auth/privacy
rules, service-side atomic idempotency, local Session usage and the offline mock.
The mock binds 127.0.0.1:0, stores one in-memory entry per key, closes/joins its threads,
and can inject errors/timeouts or drop a response after committing. It never retains
Authorization headers. It drains bounded PUT bodies before early errors so a deliberate
401 is received as an HTTP response rather than a TCP reset.

## Open questions and known limits

- No open questions block T-705. The Library team must agree to the proposed contract
  before deployment; no live service was contacted.
- The local result URL is None until an actual Reel dashboard/integration API resource
  exists. The existing LibraryEntry table stores all required fields now.
- Inside an existing transaction use upsert_library_entry(session, ...), not the
  Database-level convenience that deliberately opens its own writer transaction.
  The caller must roll back its transaction after an upsert exception. Use the project's
  immediate transaction convention for stage read-then-write work.
- T-706 will store publication results, apply retry/hold policy, and translate any
  existing metadata chapter start fields to the Library contract's start_seconds.
  This task does not register stages, expose the catalogue API or implement a UI.
- The HTTP timeout is urllib's socket-operation timeout rather than an independent
  whole-request deadline. The service must atomically preserve external-key-to-entry-id
  mappings across its own restarts; the mock's storage is intentionally in memory only.
- Dry-run is an explicit factory/constructor argument because the shared settings have
  no library.mode key. Preview results contain payload and never claim a real entry.
