## Design and public API

Both adapters share strict JSON/evidence validation and the same decision mapping.
A nonempty roster passes only when every student is explicitly granted. Denied,
unknown, missing/null or unrecognised string status means opted_out (D-019).
Unknown groups and empty rosters return unknown. Malformed data, connection/timeout
failures, and service/authentication failures return unreachable, never approval.

The file adapter reads and validates the entire registry on every check; names use
Unicode case-insensitive matching, and absent group_ref defaults to the registry name.
The HTTP adapter makes one GET using the configured base URL/timeout and a bearer token
from cfg.secrets; no retries or persistence happen here. JSON fields are allowlisted,
request/response groups must match, duplicate ids/JSON keys are rejected, and response
bodies are capped at 1 MiB. Error bodies/exceptions are not copied into decisions/logs.
Redirects and environment proxies are disabled. The mock binds 127.0.0.1:0, supports
fault injection, suppresses access logs, and joins its request threads on shutdown.

The package exports the ABC, decision/student types and factory. Concrete adapters and
mock are available from their respective modules. students_json() emits only id/status
for the later ConsentCheck.students column; it returns a fresh mutable JSON copy.
Providers do not create timestamps; ConsentCheck already supplies UTC checked_at.

The proposed contract documents GET /v1/consent, the optional ISO lesson date, response
examples, authentication, HTTP status mapping, file schema, storage and privacy.
HTTP 401/403 are deliberately unreachable because they represent inability to verify
consent, and require credential repair. Only a structured 404 group_not_found is unknown.

D-016 support: make_consent_provider(cfg, dry_run=True) suppresses HTTP and records the
intended GET path in the decision message and reel.consent logging. It returns
unreachable without student evidence; simulated consent never passes. Local file
checks still evaluate the actual registry. Existing ConsentSettings has no mode key;
the default file provider is offline, and explicitly selecting http enables live
checks unless dry_run=True is supplied.

## Open questions and known limits

- No unresolved implementation questions. The Core Engine team must agree to the proposed
  REST contract before a real deployment; the live service was not contacted.
- The interim file stores current consent only and does not implement historical
  lesson-date lookup. The HTTP contract carries lesson_date for the real service.
- The caller selects a group name or Core Engine id before invoking check(); T-602 should
  use the configured core_engine_group_id for HTTP where available. The factory does
  not itself translate group names/aliases.
- The urllib timeout is the standard socket-operation timeout, not a separate total
  wall-clock deadline. The providers make one attempt; retry/hold policy belongs to T-602.
- Empty rosters return unknown rather than passing without affirmative student evidence.
  Unknown status strings normalise to unknown; structurally invalid types make the
  response unreachable. Extra names/emails/profile fields are rejected, not retained.
- No production publishing, stage registration, database writes or credential changes
  are included. The only outstanding required check is the prior report's formatting
  fix listed under Requested changes.
