## What to build
1. **Outbox over `job_events`** (so restarts never lose or repeat a notification): a
   `StaffNotifier(db, cfg, client=None, clock=...)` with `run_once() -> int` that reads job events
   with an id above a watermark stored in `AppMeta` key `notifications.last_event_id`, sends one
   message per relevant event in id order, and advances the watermark after each successful send
   (in its own short transaction). On the very first run (no watermark) start from the current
   newest event id — do not flood staff with history. A retryable Slack error stops the run and
   leaves the watermark (next run retries); a permanent error is logged and the event is skipped.
   Also a `run(stop: threading.Event)` loop (poll interval 30 s, injectable).
2. **Which events** (filtered by `notifications.events`):
   - `failed` → `EventKind.FAILED` (stage, error, attempts);
   - `on_hold` → `EventKind.HELD` (stage, reason, message: consent or identification);
   - `flagged` → `EventKind.STAGE_COMPLETED` of the `import` and `transcribe` stages when the job
     has flags at that moment (list them, e.g. `unknown_group`, `empty_transcript`).
3. **Message** (Armenian, short): what happened, group and lesson (or the file name if unknown),
   stage, the reason/error, and the dashboard link `{web.base_url}/jobs/{job_id}`. Escape values
   like T-703. Also log every notification (`reel.notify`) — in dry-run only the log is written
   and no HTTP call is made. Live mode needs `SLACK_BOT_TOKEN` and a valid channel ID.
4. Metadata on each Slack message: `{"event_type": "reel_staff_alert",
   "event_payload": {"job_id": ..., "event_id": ...}}`.

## Acceptance criteria (from TASKS.md) — each needs a test
- one notification per transition (a second `run_once` sends nothing new; a restart with a new
  `StaffNotifier` continues from the watermark; the first run skips history);
- the content includes stage, error/reason and the dashboard link;
- plus: event filter from config; dry-run makes no calls; retryable error → retried next run,
  permanent error → skipped and logged; Armenian text intact.
Create the jobs and events through the real `JobQueue` (claim → fail / hold) where practical.
