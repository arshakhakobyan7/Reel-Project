## Design and public API

The stdlib urllib client implements chat.postMessage, chat.update, chat.getPermalink,
and conversations.history. It uses the handoff's POST/UTF-8 JSON transport, bearer auth,
an injectable base URL and timeout, bounded JSON responses, and sanitised errors.
Redirects and environment proxies are disabled; HTTP base URLs are permitted only on
127.0.0.1 for local tests. Unknown upstream error strings/bodies are not echoed.

The DB-agnostic publisher renders SlackSettings.message_template using POST_FIELDS,
escapes &, < and > in formatted field values, and preserves template literals/markup.
A saved channel:ts id takes the update path directly. Otherwise cursor-paginated history
is searched with include_all_metadata=true for reel_video metadata matching this job.
A recovered message is updated; a new one is posted only after the search is complete.
Every write includes the job metadata. A permalink is fetched and returned for storage.

An unreadable/malformed/incomplete history or cursor cycle raises a retryable error;
it never falls through to posting blindly. A crash/lost response after a committed post
is recovered by metadata on the next attempt. Permalink errors carry the already known
external_id on SlackError so the stage can persist it before retrying. Updating a saved
id that was deleted fails permanently instead of silently posting another message.

Public API in reel.publish.slack (Date below is datetime.date):

```text
SlackError(code: str, *, retryable: bool, retry_after: float | None = None,
           external_id: str | None = None)
  attributes: code, retryable, retry_after, external_id

SlackClient(token: str | None, *, base_url: str = "https://slack.com/api/",
            timeout_seconds: float = 15.0)
SlackClient.post_message(channel: str, text: str,
                         metadata: dict[str, Any]) -> dict[str, Any]
SlackClient.update_message(channel: str, ts: str, text: str,
                           metadata: dict[str, Any]) -> dict[str, Any]
SlackClient.get_permalink(channel: str, ts: str) -> str
SlackClient.history(channel: str, *, cursor: str = "", limit: int = 100) -> dict[str, Any]

SlackPost(job_id: int, channel: str, title: str, url: str,
          summary: str = "", group: str = "", lesson: int | str = "",
          date: Date | str = "", duration: float | str = "",
          instance_id: str | None = None)  # frozen dataclass
SlackPost.metadata() -> dict[str, Any]

SlackResult(external_id: str | None, url: str | None, text: str,
            created: bool, dry_run: bool)  # frozen dataclass; updated: bool property

render_message(template: str, post: SlackPost) -> str
SlackPublisher(settings: SlackSettings, *, token: str | None = None,
               client: SlackClient | None = None, history_page_size: int = 100,
               max_history_pages: int = 100)
SlackPublisher.publish(post: SlackPost, previous: str | None = None) -> SlackResult
make_slack_publisher(cfg: LoadedConfig) -> SlackPublisher
```

The factory uses cfg.settings.slack and cfg.secrets.get("SLACK_BOT_TOKEN"). The caller
resolves the group's slack_channel through cfg.groups before constructing SlackPost.
No global environment/private config is read directly by the publishing adapter.

Metadata is {"event_type":"reel_video","event_payload":{"job_id":7}}. When instance_id
is supplied it is included in event_payload and matched during recovery, preventing
cross-database job-id collisions (D-027). String and integer job ids in existing metadata
are recognised; booleans are not. The caller should supply the real DB instance_id.

SlackResult.external_id is channel:ts and fits PublicationTarget.external_id for normal
Slack identifiers. The stage stores external_id, url, dry_run and its chosen details,
such as text/created/updated. Dry-run returns rendered text, no external id/permalink,
created=False, updated=False, dry_run=True and performs no HTTP, even without a token
or configured channel. Missing/invalid tokens in live mode cause a clear permanent error.

HTTP 429 and Slack ratelimited errors expose Retry-After seconds when valid. HTTP 5xx,
connection/socket timeout failures and known temporary API errors are retryable.
Authentication/channel/membership/scope/editing errors are permanent. Unrecognised API
error codes become a sanitised permanent api_error. No internal retries or sleeps occur;
T-706 controls scheduling and must honour retry_after where present.

## Sources consulted and known limits

The official [chat.postMessage](https://docs.slack.dev/reference/methods/chat.postMessage/),
[chat.update](https://docs.slack.dev/reference/methods/chat.update/),
[conversations.history](https://docs.slack.dev/reference/methods/conversations.history/),
[chat.getPermalink](https://docs.slack.dev/reference/methods/chat.getPermalink/), and
[message formatting](https://docs.slack.dev/messaging/formatting-message-text/) references
were checked. History metadata/pagination, error handling, and escaping follow these
references; the requested permalink transport exception is described above.

- Real Slack credentials/workspace calls were unavailable and were not requested for
  these tests. Live API transport, workspace scopes and bot membership remain for T-1003.
  The app needs chat:write and the appropriate conversation-history scopes to recover posts.
- Metadata recovery requires that Slack exposes the original message and metadata.
  Messages hidden/deleted by retention cannot be recovered from history. A persisted
  previous id is therefore important for long-term reruns.
- History search checks at most max_history_pages (default 100) of history_page_size
  (default 100). If incomplete it fails safely; it does not create another message.
  Callers can adjust these constructor limits for larger channels.
- History-then-post is not an atomic Slack operation. Existing job leases/stage orchestration
  must prevent concurrent attempts for the same job. Sequential retries and crash recovery
  are tested; no cross-process exactly-once guarantee is claimed.
- Existing duplicate messages are not deleted. The first matching history message is updated.
  Moving a saved publication to another channel fails explicitly and needs a staff decision.
- Template fields support normal Python format specs/conversions; attribute/index lookups
  and nested dynamic specs are rejected. Only field values are escaped, so staff can keep
  intentional Slack markup in the template itself.
- Unknown API errors default to permanent; the stage receives no raw upstream diagnostics
  or token-bearing exception causes. No retry policy, notifications or publishing DB writes
  are implemented here.
