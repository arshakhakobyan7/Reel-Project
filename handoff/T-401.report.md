## Design and public API

`analyze_silence` first uses the existing `probe`, then launches one FFmpeg analysis process
with the first available audio/video streams explicitly mapped. Audio uses
`silencedetect=noise=<noise_db>dB:d=<min_silence_seconds>`. Video uses
`fps=5,scale=160:-2,freezedetect=n=<freeze_noise>:d=<min_silence_seconds>`. Both feed the
same null output. All detection thresholds and padding come from `SilenceSettings`.

The shared `run_ffmpeg` does not expose stderr. A private local runner therefore retains
detection-event lines, keeps the last 20 diagnostic lines for failures, drains stderr in a
thread, and reads `-progress pipe:1` in the calling thread. It uses the shared progress and
callback types and raises `FfmpegCancelled` / `FfmpegError`. Callback failures and cancellation
kill and reap the process, join the reader, and close the pipes. No shared runner was edited.

Public API, all in `reel.cleaning.silence`:

```python
@dataclass(frozen=True)
class Interval:
    start: float
    end: float

@dataclass(frozen=True)
class Removal(Interval):
    reason: str

@dataclass(frozen=True)
class SilenceAnalysis:
    silences: list[Interval]
    freezes: list[Interval]
    removals: list[Removal]

def parse_detection_log(
    output: str | Iterable[str], duration: float
) -> tuple[list[Interval], list[Interval]]: ...

def intersect_intervals(
    left: Sequence[Interval], right: Sequence[Interval]
) -> list[Interval]: ...

def removable_silences(
    silences: Sequence[Interval],
    freezes: Sequence[Interval],
    settings: SilenceSettings,
) -> list[Removal]: ...

def analyze_silence(
    ffmpeg: Path | str,
    ffprobe: Path | str,
    source: Path | str,
    settings: SilenceSettings,
    *,
    on_progress: Progress | None = None,
    on_cancel: CancelHook | None = None,
) -> SilenceAnalysis: ...
```

The parser clips detections to the media duration, closes open intervals at EOF, ignores
unmatched ends and duration-only messages, and merges overlapping/touching intervals.
Intersection accepts unordered inputs without modifying them. With the static gate enabled,
the overlap itself must reach the configured minimum; otherwise the detected silence must.
Padding is applied afterwards, on both sides. Reasons are `"silence over a static picture"`
and `"silence"`. Removals are ordered; raw detections remain unpadded.

No audio means no silences or removals. Video-only media with known duration still reports
freezes; without a usable duration it returns empty results. Audio-only media has no freeze
intervals and is deliberately not treated as static: there is no picture evidence. Its
silences can be removed when `require_static_video=False`.

## Open questions and known limits

- No open questions block T-401. T-404 can consume `SilenceAnalysis.removals`; T-406 remains
  responsible for pipeline integration and persistence.
- Picture analysis samples at 5 fps and 160 pixels wide. Freeze boundaries have approximately
  0.2-second sampling granularity, and motion below that resolution/tolerance may be missed.
  Frame alignment and rendering belong to later tasks.
- Only the first audio and video streams are analysed, matching the existing media helpers.
- Media with audio needs a known, finite, positive duration to close intervals reliably.
  Otherwise `InvalidMedia` is raised. The no-audio case returns no silences without that error.
- Cancellation/progress apply to the analysis process. Initial metadata probing uses the
  existing synchronous `probe` API.
- The minimum is checked before `keep_seconds` is subtracted, as requested; a resulting
  removal can therefore be shorter than `min_silence_seconds`.
