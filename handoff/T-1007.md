# T-1007 — Dashboard design: dark brand colour system (user request, 2026-11-20)

Read `handoff/README.md` first. Its hard rules apply, with the file list below.

## Goal

Give Reel's staff dashboard (`src/reel/web/`) a new visual design, following the user's
direction below. **Only the look changes.** Behaviour, routes, form fields, Armenian texts and
security stay exactly as they are.

## The user's design direction (verbatim)

```
Create a cohesive color system for my product's website inspired by
https://picsartacademy.am/.

The visual direction is a dark, expressive technology brand:
charcoal surfaces, crisp light text, vibrant magenta actions, and fresh
mint accents. Adapt this palette to the product's existing layout.

Use these verified reference colors as reusable CSS variables:

:root {
  --background:       #111111;
  --surface:          #1F1F1F;
  --surface-elevated:  #333333;
  --border-subtle:    #333333;
  --border-strong:    #4D4D4D;

  --text-primary:     #FCFCFC;
  --text-secondary:   #D0D0D0;

  --brand-primary:    #D500C8;
  --brand-bright:     #FF3DF3;
  --brand-pink-soft:  #FFA3F9;
  --brand-pink-tint:  #FFD6FD;

  --brand-secondary: #71FFEA;
  --brand-mint-light:#A3FFF1;
  --brand-mint-tint: #D6FFF9;
}

Apply the colors with a clear hierarchy:

- Use #111111 for the page background and #1F1F1F for cards,
  navigation, forms, and panels. Use #333333 for elevated surfaces.
- Use #FCFCFC for headings and main text; #D0D0D0 for supporting text.
- Make magenta the primary action color: main buttons, active
  navigation indicators, and important interactive accents.
- Use bright pink for small highlights and expressive decorative details.
- Use mint for secondary emphasis, focus indicators, selected states,
  and occasional feature or callout panels.
- Pair mint and pale accent backgrounds with #111111 text.
- Keep most surfaces neutral. Give large colored panels a deliberate
  purpose; keep data-heavy views visually quiet.

For accessible button states, use:
- Primary: #D500C8 background with pure white #FFFFFF labels.
- Primary hover: #A8009E background with #FFFFFF labels.
- Secondary: #71FFEA background with #111111 labels.
- Secondary hover: #A3FFF1 background with #111111 labels.

Check text contrast across default, hover, focus, and disabled states.
Keep functional success, warning, and error colors distinct from the
brand palette, and accompany status colors with labels or icons.

Use spacious, readable typography with Armenian support. Favor solid
color blocks, clear surface hierarchy, and restrained accents.

Implement the palette centrally and apply it consistently to buttons,
links, cards, inputs, navigation, dialogs, and empty states.
```

## Reel's constraints (from the lead developer; they come first where they conflict)

1. **Your files:**
   - `src/reel/web/static/style.css`: rewrite it. All colours live as CSS variables in
     `:root`, and nowhere else.
   - `src/reel/web/templates/*.html`: only `class` attributes and purely presentational
     wrapper elements, where the design needs them.
   - Everything else is read-only, including `static/upload.js`, `texts.py`, the Python code
     and **all existing tests**.
2. **CSP stays as it is** (`src/reel/web/app.py`): `default-src 'self'; style-src 'self';
   script-src 'self'`.
   - No `style="..."` attributes, no `<style>` blocks, no inline scripts.
   - No external fonts, CDNs, images or frameworks (also D-009: free and local).
   - Use system fonts with Armenian coverage, for example `"Segoe UI", "Noto Sans Armenian",
     Sylfaen, Arial, sans-serif`.
3. **Keep the markup the tests and the upload script rely on.** Do not rename or remove:
   - form field names;
   - element ids (`upload-form`, `files`, `file-list`, `upload-status`, `upload-total`,
     `start`, `stop`, `known-groups`, `release-note`, ...);
   - `data-*` attributes;
   - routes, link targets, the CSRF hidden inputs;
   - the existing class names used by JavaScript or tests (`small-button`, `player`,
     `pill-*`, `status-*`, `cutbar`, `kept`, `removed`, ...).

   You may add classes. Run the whole suite. If a test fails because of your markup change,
   undo that change; do not edit the test.
4. **The design is dark only.**
   - Remove the light theme and the `prefers-color-scheme` switch.
   - Set `color-scheme: dark`, so the browser's own controls (date picker, file input,
     scrollbars, `<video>` controls, `<progress>`) are dark too.
5. **Contrast (WCAG 2.1 AA: 4.5:1 for normal text, 3:1 for large text and UI parts).**
   - `#D500C8` on `#111111` is only about 4.2:1, and about 3.7:1 on `#1F1F1F`. So **text
     links and magenta text on dark surfaces use `--brand-bright` (#FF3DF3) or
     `--brand-pink-soft`**. Keep `#D500C8` for button backgrounds, active indicators and
     borders.
   - White on `#D500C8` is about 4.5:1, right at the limit: make primary button labels at
     least 16 px and semibold.
   - Put a table of the computed ratios for every text/background pair you use in the report.
     Compute them; do not estimate.
6. **Status colours** for the stage pills and status badges (`queued`, `running`, `on hold`,
   `failed`, `done`, `cancelled`, `retry`):
   - Make them distinct from magenta and mint (success green must not look like the mint
     accent).
   - Each pill and badge already has a text label; keep it.
   - **Failed** must stand out. **Done** must look calm.
   - Check the colours of the cut bar (`.cutbar .kept`, `.cutbar .removed`; SVG `fill` in CSS)
     on the dark background.
7. **Pages to cover** (all templates):
   - `login`;
   - `recordings` (the list: filters, counts, table, pills, pager);
   - `recording` (detail: facts, the video player, the cut bar, chapters, metadata, the staff
     action forms, the history table);
   - `upload` (form, file list with ↑ ↓ buttons and progress bars);
   - `metrics`;
   - `error`.

   Also cover these states:
   - focus (a visible mint focus ring on every interactive element; keyboard use matters);
   - hover;
   - disabled (`button:disabled`, for the ↑ ↓ buttons);
   - the `notice` (success), `error` and `hold` boxes;
   - empty states ("nothing here" texts in `.muted`).
8. **Layout stays as is** (responsive, `max-width` page). Keep it usable at 360 px wide: the
   tables scroll inside their `.table` wrapper.

## Acceptance criteria

- `style.css` defines the palette once, as the variables above, plus status, focus and state
  variables. No hex colour appears outside `:root`.
- Every page and state listed in point 7 is styled with the hierarchy described by the user.
- The contrast table is in the report, and every pair passes AA (or AA large, where it is
  large text or a UI part).
- No inline styles or scripts, and no external resources (CSP unchanged).
- The whole suite and ruff pass:
  ```powershell
  .venv\Scripts\python -W error -m pytest -q
  .venv\Scripts\ruff check .
  .venv\Scripts\ruff format --check .
  ```
