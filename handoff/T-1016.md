# T-1016 — "My page": every account sees and updates its own details and password

User request, 2026-11-21. Read `handoff/README.md` first. Its hard rules apply, with the file
list below. Decisions: D-065 (accounts), D-068 (this task).

## The user's request (verbatim, Armenian)

> Օգտատերերի էջերի համար (Նաև admin-ի) կա մի խնդիր: Նրանք չունեն իրենց տվյալները ստուգելու
> նաև թարմացնելու համար նախատեսված էջ (Օրինակ գաղտնաբառը փոխելու): Դա պետք է շտկվի:
>
> Նաև user-ի էջից պետք է հանել ծախս և ժամանակ պատուհանը

In English, it asks for two things:

- Every account, the admin's too, needs a page to check and update its own details, for
  example to change the password.
- The "Ծախս և ժամանակ" (cost and time) panel must be removed from the user's recording page.

How sessions work: every request reads the account again (`_load_staff`). A session holds
`password_fingerprint(password_hash)`, so **changing the hash ends every session of that
account**. The current browser keeps its session only if you give it a new one, as `/login` and
`/register` do: `request.state.replace = state.signer.new(user_id=..., fingerprint=...)`.

## What to build

### Part A — `/profile` ("Իմ էջը")

1. **The page.**
   - `GET /profile`, for any signed-in account (dependency `staff`). An anonymous visitor goes
     to the login page, as on every other page. A closed account cannot reach it.
   - There is **no account id in the URL**: the page and its forms work only on the signed-in
     account, so nobody can change someone else's account.
   - Add a nav link **«Իմ էջը»** in `base.html` for every signed-in account, with `is-active`
     on `/profile`. Also make the name in the header (`.who`) a link to `/profile`.
2. **Read-only facts:**
   - the username ("Մուտքի անուն");
   - the role (`texts.ROLE_LABELS`);
   - YouTube: «Տեղադրում է YouTube-ում» or «Միայն մշակում» (`Staff.publishes`);
   - when registered and the last sign-in, in the configured time zone (`views.local_text`).
3. **Form 1 «Իմ տվյալները»: first name, last name, email, phone.**
   - `POST /profile/details`. Prefill the current values.
   - **Validation:**
     - The same rules and Armenian messages as registration: refactor the field checks in
       `forms.py` into shared helpers. `parse_registration` must keep its exact behaviour and
       messages.
     - First and last name are required. `display_name` becomes `"first last"`.
     - The phone is optional; clearing it saves `NULL`.
     - The email is required when the account signs in with an email (its `username` contains
       `@`, i.e. it registered). It is optional for accounts made with `reel user add` (for
       example `admin`).
     - An email already used by **another** account, as its `email` or its `username`, is
       refused with `texts.EMAIL_TAKEN` and status 409. Check and write in one
       `db.transaction(immediate=True)`.
   - **`username` never changes.** Job events (`JobEvent.actor_name`), uploads (`upload.json`
     owner) and the admin's account page refer to it.
   - **Sign-in by email.** Change `_check_login` in `app.py` so that the typed value may be
     the username **or** the account's current email (both normalized with
     `normalize_username`). If one account has it as username and another as email, the
     username wins. Keep it one lookup, and keep `verify_password` running with the dummy
     hash when nothing is found, so the time does not tell whether an account exists. After an
     email change, the new email and the username both sign in.
   - **On success:** redirect 303 to `/profile?done=details` and show «Տվյալները պահպանվեցին։».
     The header shows the new name at once.
   - **On a mistake:** re-render with the Armenian error, 422 (409 for a taken email), and
     keep what was typed.
4. **Form 2 «Գաղտնաբառ»: current password, new password, new password again.**
   - `POST /profile/password`.
   - **Checks, in this order:**
     1. Throttle: if `state.throttle.blocked(f"user:{username.casefold()}",
        f"client:{client}")` (the same keys as `/login`), answer `texts.LOGIN_THROTTLED`
        with 429.
     2. The current password must verify. If it does not:
        - count it as a failed login with the same keys: `state.throttle.failed(...)`;
        - answer «Ընթացիկ գաղտնաբառը սխալ է։» with 422.
     3. The two new passwords must match: «Գաղտնաբառերը չեն համընկնում։».
     4. `check_password_rules`, with the same Armenian message as registration.
     5. The new password must differ from the current one: «Նոր գաղտնաբառը պետք է տարբերվի
        ընթացիկից։».
   - **On success:**
     - save `hash_password(new)`;
     - give this browser a new session with the new fingerprint;
     - redirect 303 to `/profile?done=password` and show «Գաղտնաբառը փոխվեց։ Մյուս սարքերում
       մուտքը փակվեց։».
     - Every other session of the account ends by itself.
   - Never put a password back into the form, the page, a log line or an exception message.
5. **Logging** (`logging.getLogger("reel.web")`): «account %d updated its details» and
   «account %d changed its password». Log only the id: no names, emails, phone numbers,
   passwords or hashes.
6. **Security.**
   - Both forms carry the CSRF hidden input `<input type="hidden" name="csrf_token" value="{{ csrf }}">`.
     The existing guard checks it.
   - Use `Form(max_length=...)` limits like `accounts.py`.
   - The CSP stays as it is: no inline styles or scripts.
7. **Texts.** Put the new Armenian texts in `texts.py`, including the `done` messages, as
   `PROFILE_MESSAGES`, like `ACCOUNT_MESSAGES`.

### Part B — no "Ծախս և ժամանակ" panel for users

- A user's page must not contain it: no processing time, budget, Whisper, render or LLM
  figures, and no tokens.
- The admin's page stays as it is. The `/metrics` page is already admin-only; do not change it.

## Acceptance criteria → tests in `tests/unit/test_profile.py`

1. A user and the admin each see their own data on `/profile`. An anonymous visitor is sent
   to the login page. A closed account cannot open it.
2. The nav shows «Իմ էջը» to every signed-in account.
3. **Details:**
   - they are saved;
   - the header shows the new name;
   - the admin's `/admin/users/<id>` shows the new values;
   - the phone can be cleared.
4. **Details mistakes** (each refused with its Armenian message, the typed values kept):
   - an empty first or last name;
   - a wrong email or phone;
   - an empty email for a registered account.
5. The admin (an account without `@` in its username) may save the details with an empty
   email.
6. An email used by another account, as its email or its username, is refused with 409.
7. **After an email change:**
   - signing in works with the new email and with the username;
   - the old email of another account cannot be taken;
   - the admin's account page still lists the user's earlier actions.
8. **Password changes refused** with their messages:
   - a wrong current password;
   - mismatched new passwords;
   - a new password that is too short;
   - a new password equal to the current one.
9. Repeated wrong current passwords are throttled (429) like failed logins.
10. **A successful password change:**
    - this client stays signed in;
    - another client signed in before is signed out (its next request goes to the login page);
    - the old password no longer signs in, and the new one does.
11. A POST without the CSRF token is refused (the existing behaviour).
12. No password appears in the log records (`caplog`) or in any page.
13. **Part B:**
    - a user's recording page has no «Ծախս և ժամանակ», `Whisper`, `token` or «բյուջե»;
    - the admin's page of the same recording still has the section.
