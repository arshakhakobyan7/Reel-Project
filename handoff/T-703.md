## What to build
1. A thin Slack Web API client over stdlib `urllib.request` (HTTPS POST JSON to
   `https://slack.com/api/<method>`; base URL injectable for tests): `chat.postMessage`,
   `chat.update`, `chat.getPermalink`, `conversations.history` (with `include_all_metadata`).
   Handle `ok: false` errors (classify retryable: `ratelimited`/HTTP 429 with `Retry-After`, 5xx,
   timeouts; permanent: `invalid_auth`, `channel_not_found`, `not_in_channel`, ...), never log the
   token.
2. `SlackPublisher` — DB-agnostic (the T-706 stage stores the result):
   `publish(post, previous) -> SlackResult` where `post` holds job id, channel, and the template
   fields (`POST_FIELDS`), and `previous` is the stored `external_id` (channel + ts) or `None`.
   - Message text from `message_template` (escape Slack's `&`, `<`, `>` in field values).
   - Message metadata `{"event_type": "reel_video", "event_payload": {"job_id": ...}}`.
   - Idempotency: with `previous` → `chat.update` that message; without it → first look in
     recent channel history for a message with this job's metadata (a crash may have happened after
     posting), update it if found, otherwise post a new one. One message per job across retries.
   - Return `external_id`, permalink `url`, whether it was created or updated, and `dry_run`.
3. Dry-run (`mode = "dry-run"`): render and return the text, make **no** HTTP call.
   Live mode without a token → clear permanent error.
