## What to build
1. **One fast analysis pass** with FFmpeg: `silencedetect` (noise = `noise_db`, d =
   `min_silence_seconds`) on the audio and `freezedetect` (n = `freeze_noise`,
   d = `min_silence_seconds`) on a low-resolution, low-fps copy of the picture (e.g. 160 px wide,
   a few fps), output to `-f null`. Support `on_cancel` / `on_progress` like `run_ffmpeg`
   (reuse it if it gives you stderr; otherwise extend locally in your module, do not edit
   `ffmpeg.py` — request the change instead).
2. **Pure, separately tested functions**: parse the FFmpeg log into silence and freeze intervals
   (an interval still open at the end of the file ends at the media duration); intersect them.
3. **Removable silences**: if `require_static_video`, removable = silence ∩ static picture, and the
   overlap itself must last at least `min_silence_seconds`; otherwise every detected silence.
   Shrink each by `keep_seconds` at both sides. Result: an ordered list of a small frozen dataclass
   (`start`, `end`, `reason`), with reasons such as `"silence over a static picture"` / `"silence"`.
   Also return the raw silence and freeze intervals (useful for the dashboard and for T-404).
4. A media file without an audio stream gives no silences (no exception); a video-less file is
   treated as "static" only if you document why.
5. All thresholds come from `SilenceSettings`; nothing hard-coded except the analysis scale/fps.

## Acceptance criteria (from TASKS.md) — each needs a test
- a long silence over a static picture is removable;
- a long silence over a changing picture is kept (when `require_static_video`);
- a short silence is kept;
- thresholds come from config (e.g. the same file gives a different result with other settings);
- plus: `keep_seconds` is applied; a silence at the very end of the file is found.

Keep integration media short (≤ 40 s total, 320x240) so the suite stays fast.
Do NOT build the pipeline stage (that is T-406).
