## What to build
1. `publish(job_id, item) -> LibraryResult` (entry id/url, created vs updated).
2. Local: idempotent upsert by `job_id` (re-runs update the same row; `updated_at` moves). Must be
   safe when called inside the stage's own transaction too — offer a `Session`-level function and a
   `Database`-level convenience.
3. HTTP: idempotent `PUT /entries/{external_key}` where the key is stable across retries and unique
   across Reel installations (database `instance_id` + job id); bearer token from
   `LIBRARY_API_TOKEN`, never logged; timeout from settings; strict response validation;
   retryable (timeout, 5xx, 429) vs permanent errors (4xx) as distinct exceptions.
4. Contract doc: endpoint(s), JSON examples, status codes, auth, idempotency rule. Short.

## Acceptance criteria (from TASKS.md) — each needs a test

- fields: title, link, group, lesson, date, chapters (Armenian text survives round trip);
