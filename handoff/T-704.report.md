## Public API

```python
@dataclass(frozen=True)
class ClassroomPost:
    job_id: int
    course_id: str
    title: str
    url: str
    summary: str = ""
    group: str = ""
    lesson: int | str = ""
    date: Date | str = ""
    duration: float | str = ""
    instance_id: str | None = None
    def marker(self) -> str: ...

@dataclass(frozen=True)
class ClassroomResult:
    post_id: str | None
    post_type: Literal["announcement", "material"]
    url: str | None  # The API's alternateLink, not a constructed URL.
    created: bool
    dry_run: bool
    body: dict[str, Any]
    details: dict[str, Any]
    @property
    def updated(self) -> bool: ...

def render_text(template: str, post: ClassroomPost) -> str: ...

class ClassroomPublisher:
    def __init__(self, settings: ClassroomSettings, tokens: AccessTokens | None = None, *,
                 api_url: str = "https://classroom.googleapis.com/v1/",
                 timeout_seconds: float = 30, page_size: int = 100,
                 max_history_pages: int = 100) -> None: ...
    def publish(self, post: ClassroomPost, previous: dict[str, Any] | None, *,
                on_state: Callable[[dict[str, Any]], None] | None = None,
                check: Callable[[], None] | None = None) -> ClassroomResult: ...
```

## Design

- The group's resolved `classroom_course_id` becomes `ClassroomPost.course_id`. Template fields
  match `POST_FIELDS`, including ordinary format specs for lesson/date/duration. Attribute/index
  access and nested format specs are rejected. Text remains literal Unicode; JSON uses the shared
  client's UTF-8 encoding. Limits are 30000 text characters including the footer, 3000 material
  title characters and 2024 link characters. Invalid inputs fail before HTTP.
- Announcements contain `text`; course-work materials contain `title` and `description`. Both
  are created with `state=PUBLISHED` and `materials=[{"link": {"url": post.url}}]`. Dry-run returns
  this body without constructing an HTTP client, obtaining a token or inventing an external ID.
- A single short reference footer, `Reel · <16 hexadecimal characters>`, is appended to the
  text/description. It is derived from SHA-256 of the optional database-instance namespace and
  job ID, so it stays stable when title, video URL or post type changes. It is visible plain text,
  with no hidden characters or HTML comments. This supplies recovery identity in one unobtrusive
  line. T-706 should pass the DB's stable `instance_id`, as it does for Slack.
- Stored post ID/type is retrieved first. With the same attached video, only mutable fields are
  patched (`text,state`, or `title,description,state`). `materials` never enters a PATCH mask/body.
- Without a usable stored post, history is paginated by descending update time, including
  PUBLISHED and DRAFT posts. A matching URL or exact final marker line identifies an existing
  post. The desired URL takes precedence over an older marker match, so a replacement whose
  create response was lost is recovered. The history bound is configurable through constructor
  arguments; an incomplete/cyclic/malformed history lookup fails instead of creating blindly.
- Google can upgrade a submitted link into a `youtubeVideo` attachment. Recovery recognises
  both link materials and the returned YouTube video ID/alternateLink. A normal same-video re-run
  therefore keeps its post even after this API conversion.
- Changed attachments require replacement for both supported types under the stable API.
  The new published post is created first, its ID is checkpointed, its alternateLink is resolved,
  and only then are old posts deleted. The material preview capability does not permit editing
  attachments of published course-work material; this implementation uses no preview API.
  These choices follow the official [announcement patch fields](https://developers.google.com/workspace/classroom/reference/rest/v1/courses.announcements/patch)
  and [course-work-material patch restrictions](https://developers.google.com/workspace/classroom/reference/rest/v1/courses.courseWorkMaterials/patch).
- Checkpoints include `version`, `job_id`, `marker`, `course_id`, `post_type`, `video_url`, the
  resulting `post_id`/`url` when known, `pending_delete`, `complete` and `dry_run`. Pending deletions
  contain post IDs/types, not credentials. Each `on_state` argument and the result details are
  independent copies. Replacement intent is saved before create, and the new ID before deleting
  old posts. Cleanup is retryable after a lost DELETE response. Same-marker duplicates found
  during recovery are cleaned up after the chosen post is published; unrelated posts are retained.
- Deleted posts are recreated. A deleted-state response, item 404, or a patch/delete 400 followed
  by a confirmed missing/deleted post is handled without treating arbitrary 400 errors as deletion.
  Switching post type with stored state also creates the new type before cleaning up the old one.
- All HTTP uses unchanged `GoogleApiClient`, `AccessTokens` and `GoogleApiError`. The client's
  single 401 refresh/retry is reused. Permanent 403 errors explain teacher membership, OAuth
  scopes and the creating developer project; collection/create 404 explains course access and
  teacher membership. Retryable quota/rate/5xx errors retain their classification. No request
  bodies, headers or token values are logged; success logging contains only a job ID.
- The return URL must be the API's published Classroom `alternateLink`. Missing URL triggers
  a GET after saving the ID. A draft or invalid alternateLink cannot be reported as success.
  `check()` is called around requests and state persistence; cancellation/callback failures
  propagate to the caller.

## Open questions / known limits

- No unresolved publisher behaviour questions. The shared Ruff exclusion change above remains
  outside the authorized files; the final unfiltered Ruff commands are not clean until addressed.
- Classroom has no atomic search-and-create idempotency key. Calls for one job must be serialized;
  recovery depends on visible marker/link history and saved state. Lookup stops safely at its bound.
- `on_state` is optional, but durable checkpoints are needed for reliable cross-type replacement
  cleanup. With no stored state, recovery searches only the configured post type, as requested.
- The API requires the creating developer project for updates/deletes, in addition to course access.
  A same-link post created by another project may therefore be found but cannot be modified by Reel;
  this produces a clear permanent permission error rather than an extra post.
- Changing the stored course/job/instance identity is refused to avoid editing another destination.
- HTTP is synchronous and bounded by the configured timeout; cooperative `check` does not interrupt
  an in-progress socket read. Live credential verification remains T-1003.
